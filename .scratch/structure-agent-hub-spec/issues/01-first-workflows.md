## Question

SPEC 面向谁，优先支持哪些具体结构工程任务，输入、输出与人工判断分别是什么，何种结果意味着 Hub 核心工作流可用？不预设平台、统一模型或全自动结构设计。

## Answer

已按用户 2026-11-06 的明确确认（「是，按此记录」）记录本票共识。本票是 planning-only 的 HITL 决策票：以下内容是 SPEC 的首批场景与验收基线，不是本轮已执行的软件测试。本轮未运行任何 MCP、CAD/BIM 或结构分析软件，未写 SPEC 正文、未搬迁代码、未开发 MCP/Skill、未部署客户端。

### 用户与首批任务方向

- 首要用户：使用结构分析/设计软件的结构工程师。
- 首批工程任务方向：读取与核查既有模型；建立或修改模型；运行结构分析。
- AI 可依据取得的数据给出初步发现与解释；最终核查与工程判断由工程师作出。
- 不假设全自动结构设计、统一模型或统一平台。

### 首批验收实例（五个现有 MCP，各至少一例）

SAP2000 是第一个贯通示例。五个现有 MCP 各至少一个适配其自身能力的实例，不要求每个软件覆盖上述三类任务中的每一类；同一软件允许不止一个实例，这也不是对其能力范围的限制。五个实例必须全部实际通过，才可认定 Hub 核心工作流整体可用。

**1. SAP2000（贯通示例：核查、改模型副本、运行分析、读结果）**

- 输入：已有门式刚架模型、要修改的指定截面参数、工程师选定的分析设置、目标节点/杆件。
- 执行顺序：先核查该截面的原值与受影响构件；确认后修改副本；工程师确认分析设置后运行分析；读取所选节点位移与杆件内力，并附可核对上下文。
- 人工判断：截面原值与受影响范围是否可接受、分析设置是否正确、结果是否可信。
- 确认粒度：修改模型前逐次确认；运行分析前再次逐次确认。
- 暂停条件：原值或受影响范围不明时暂停，待工程师核实后继续。

**2. ETABS（读既有分析结果）**

- 输入：已有分析结果的建筑模型、指定楼层与工况。
- 产出：该楼层的层间位移等结果，并附可复核的初步发现。
- 人工判断：工程师核查结果与初步发现。
- 确认粒度：只读核查，无需改动确认；不得修改原模型或原文件。

**3. MIDAS（读既有分析结果）**

- 输入：已有分析结果的模型、指定工况与查询对象。
- 产出：位移或杆件内力，供工程师核查。
- 人工判断：工程师核查数值及其上下文。
- 边界：仓库文档明确部分结果字段尚待实机验证（`F:/DotNetProgram/tgk-midas-mcp/README.md:82-84`）；本票不声称这些字段已验证。

**4. Rhino（几何查询与线段创建/调整）**

- 输入：工程师提供的结构轴线坐标与现有文档。
- 执行顺序：查询已有几何；确认后创建或调整线段；回读对象几何。
- 人工判断：轴线坐标与几何的对应关系、回读几何是否符合意图。
- 确认粒度：创建或调整（模型改动）前逐次确认。
- 边界：几何操作不等同于已完成的结构分析模型。

**5. YJK（新建 YDB 并回读核对）**

- 输入：工程师提供的结构几何与必要属性。
- 执行顺序：预览；确认后创建新 YDB；回读构件与模型信息核对。
- 人工判断：预览是否反映意图、回读的构件与模型信息是否正确。
- 确认粒度：一次完整预览的模型创建即使包含多个构件，也可以确认一次；该确认不授权后续独立修改或分析。
- 边界：不假设此 MCP 提供结构分析求解（其文档工具清单未列分析求解入口，`F:/DotNetProgram/tgk-yjk-modeling-mcp/README.md:31-45`）。

### 人工确认

- 每项独立的模型改动、每次分析运行前，均需工程师逐次明确确认。
- 确认前展示：目标、拟改内容（必要时含原值与新值）、已知影响、分析设置；未知影响须如实标注为未知。

### 原文件与未保存状态

- 修改现有工程默认先另存新副本。
- 覆盖已有文件必须另行明确确认。
- 打开的工程若有未保存内容，先由工程师选择「使用当前会话状态另存副本」或「使用已保存文件」；选择前不覆盖原文件。

### 只读核查的副作用

- 只读核查不得修改原模型或原文件。
- 若读取需临时切换结果输出工况等选择，必须恢复原选择；恢复不了须明确报告，该核查实例不通过。
- 现有 SAP2000/ETABS 文档记载结果工具会自行执行 `DeselectAllCasesAndCombosForOutput` 与 `SetCaseSelectedForOutput`（`F:/DotNetProgram/tgk-sap2000-mcp/README.md:184`、`F:/DotNetProgram/tgk-etabs-mcp/README.md:146`），因此不能声称现已保证恢复；恢复行为属未来须实现并验证的约束。

### 输出上下文与未知

- 输出须标注适用的来源模型/文件、对象或楼层、工况/组合、单位、坐标/方向等上下文；未知不得猜测冒充事实。
- 输入不足、结果缺失、功能不支持或调用失败，须明确报告。
- 不得编造结果、不得将缺失值当作零，也不得在上述情况下宣称实例通过。

### 部分失败

- 部分执行后失败，须报告已知已执行的内容、产物位置与未知状态。
- 没有依据不得声称已回滚。

### 未来验收标准

- 五个代表实例必须全部实际运行完成。
- 每例与事先选定的可复查参照比较关键对象、适用工况、单位与数值。
- 适用的数值容差须事先明确。
- 参照可以是对照分析软件的原生结果，以及几何/YDB 的输入与回读数据。
- 任一实例未运行或不通过，整体不得宣称 Hub 核心工作流可用。
- 通过只证明指定实例在该环境的工作流可用，不等于结构安全、规范合格或替代工程师最终判断。
- 本票未确定具体测试样本、参照结果数值或容差；验收前须选定可复查的参照并明确适用的数值容差。
